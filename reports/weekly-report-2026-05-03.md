### Tough Challenges Overcome

- **spyder bridge transport panic-on-error wedged the daemon every ~30 minutes** ([spyder](https://github.com/marcelocantos/spyder)): the autoawake supervisor polls `/v1/list_devices` every 2 s. When the bridge wedged once (frequent on this laptop with two lockdown-failing iOS UDIDs), the 10 s deadline fired and the daemon panicked. launchd respawned (`KeepAlive=true`), so Claude Code sessions saw it as a hard MCP disconnect every ~30 minutes across v0.18.0 and v0.19.0. v0.19.0's `WithHeartbeatInterval(30s)` fix was real but couldn't help — the process itself was dying. Fix in v0.20.0 splits `pmd3bridge.Client.fire()` into two error classes: recoverable transport errors (`context.DeadlineExceeded`, `net.OpError`, EOF/EPIPE mid-call) WARN + return; genuine bugs (decode failures, marshal failures, unstructured non-JSON 4xx/5xx) still ERROR + panic. The bridge supervisor exists precisely so the bridge can fault without taking the daemon down; the previous panic-on-transport-error policy short-circuited that recovery
- **autoawake convergence was kicking out user-foregrounded apps every 15 s** ([spyder](https://github.com/marcelocantos/spyder)): convergence treated "KeepAwake foregrounded" as the only acceptable state; when the user launched another app or swiped to home, autoawake re-foregrounded KeepAwake within 15 s, kicking out whatever the user had brought up. Fix in v0.23.0 re-frames the target as "the user has not expressed a preference for the device to sleep." Backgrounding KeepAwake is the preference signal, observed via a Running → backgrounded transition of KeepAwake's BackBoard state. Once observed, autoawake stays passive — even if iOS later reaps the suspended KeepAwake — until the user re-foregrounds KeepAwake or unplugs the device. Bridge gains a `/v1/app_state` endpoint backed by DVT's mobile-notifications service: subscribe, drain the initial state-enumeration burst, return the matching app's `state_description` collapsed onto running/backgrounded/terminated. v0.25.0 then distinguishes spyder-initiated launches from user dismissal — `Supervisor.NoteAppLaunched(udid, bundle)` records wall-clock time of a spyder-mediated foreground-launch; `recordKAState`'s Running → backgrounded edge consults `time.Since(obs.spyderLaunchedAt) < recentLaunchWindow` (30 s) and skips the opt-out flag-set when the marker is fresh
- **unbounded pool sim leak across daemon restarts** ([spyder](https://github.com/marcelocantos/spyder)): the pool used to start with an empty in-memory inventory and call `Reconcile`, which minted `AvailableMin` fresh sims per template — orphaning the previous run's pool. `Reconcile` also ignored `TierReserved` when computing the floor, so an active reservation caused permanent overshoot. Fix in v0.28.0 lands `Adopt()` rebuilding inventory at startup from live `SimList`/`AVDList` filtered to `spyder-pool-*`, cross-referenced with a SQLite hold ledger that survives restarts; `Acquire(template, holder)` persists holds; `Release`/destroy cleans up; `Reconcile` counts available + running + reserved toward `AvailableMin` so reservations no longer cause overshoot; `pool_gc` MCP tool deletes orphaned `spyder-pool-*` sims/AVDs the daemon doesn't track (booted orphans skipped to avoid yanking sims out from under unrelated tools). v0.29.0 then drops `Reconcile` and `RunningWarm` entirely — demand-only, with `AvailableMax` LRU-on-release governing eviction
- **csp QUIC stalls on Linux but works on macOS** ([csp](https://github.com/marcelocantos/csp)): the QUIC transport passed all three tests on macOS (kqueue) but stalled mid-stream on Linux (epoll). Diagnosis: epoll's `EPOLL_CTL_ADD` registers an interest set; once a one-shot UDP fd fires, the kernel doesn't re-arm it. Fix uses `EPOLL_CTL_MOD` to re-arm one-shot UDP fd events between reads; tests wired to skip on Linux while the underlying runtime quirk was being characterised, then re-enabled once the fix landed (🎯T21)
- **buffered-channel move-before-commit corrupted in-flight values** ([csp](https://github.com/marcelocantos/csp)): the buffered channel implementation reserved a slot via `try_push_reserve` before the sender had finished assembling the payload; if the receiver pulled before commit, it observed a partially-constructed value. Fix in 🎯T20 separates reservation from commit and refuses to `recv` an uncommitted slot; reproducer test added
- **csp_net.cpp amalgamation hits a C99-vs-C++ semantic wall** ([csp](https://github.com/marcelocantos/csp)): the original design paper assumed `extern "C"` would suffice to bundle C-source files into a single `.cpp` translation unit. It turns out `extern "C"` controls *linkage*, not *parsing* — Clang has no language-switching pragma to compile sections of a `.cpp` TU as C99. The vendored set (llhttp, nghttp2, nghttp3, ngtcp2, wslay) emits ~623 hard errors when bundled (370 implicit `void*` → typed pointer conversions, 125 cascading guard collisions, 28 conflicting forward declarations across .c files, 10 implicit `int` → enum). Documented in design paper 21 with four resolution paths; the infrastructure committed (DFS sibling-header inlining, per-file static-name renaming, per-file C-source patch hooks, version.h auto-generation) is reusable for any of them. Implementer recommendation: revisit the "single .cpp TU, no separate .c files" constraint
- **Apple Vision silently returns zero observations on >10 MP screenshots** — detail in [private week 2026-05-03](https://github.com/marcelocantos/progress-reports-private/blob/master/reports/weekly-report-2026-05-03.md)
- **mcpbridge upstream restart killed the agent's stdio session** ([mcpbridge](https://github.com/marcelocantos/mcpbridge)): when the upstream HTTP MCP server restarts autonomously (`brew services restart mnemo` mid-session) it forgets the wrapper's `MCP-Session-Id` and rejects the next POST with `400 Bad Request: Invalid session ID`. The wrapper terminated, taking the agent's stdio session with it — the exact friction mcpbridge exists to eliminate. Fix in v0.6.0 distinguishes 4xx-with-active-session-id from other non-2xx via `errno=ESTALE`, gives dispatch a `STALE` vs `FATAL` return, queues message bytes for replay on `STALE`, and flows through the existing `DRAINING → SWAPPING → perform_swap → replay handshake → RUNNING + drain queue` reload pathway. v0.7.0 then closes the at-most-once delivery gap by replaying only idempotent reads transparently and surfacing structured `-32002` for side-effecting `tools/call` so the agent can decide whether to retry
- **ge Android background loses the bgfx swap chain** ([squz/ge](https://github.com/squz/ge)): when Android sends `SDL_EVENT_DID_ENTER_BACKGROUND`, the underlying ANativeWindow gets destroyed; the next `bgfx::frame` after foregrounding draws into a stale handle. Fix wires the SDL lifecycle hook to call `bgfx::reset` on `DID_ENTER_FOREGROUND`, recreating the swap chain against the new ANativeWindow; tested with multiple background/foreground cycles plus a long pause to verify nothing accumulates. Same fix folds in dual-renderer Android (Vulkan emulator / GLES real device, picked by `bgfx::RendererType` discovery) so the swap-chain recreation works under both
- **player reconnect sees an orphaned session and a black screen** ([squz/ge](https://github.com/squz/ge)): when the player app reconnects after a transient drop, the daemon-side session record is still alive but the bgfx resources have been destroyed. Fix in 🎯T25 detects the orphaned session at attach time and re-establishes resources with a fallback to the last-rendered screenshot until the next frame arrives; `TestOrphanedSessionReattach` in `daemon_test.go` covers the path
- **claudia event subscriber starvation under bulk fan-out** ([claudia](https://github.com/marcelocantos/claudia)): the v0.x `OnEvent` API was single-subscriber — any consumer that called it displaced the previous one, including the internal `WaitForResponse` consumer. Under bulk fan-out (claudia driving a pool of 5+ tasks) consumers stomped on each other and events vanished. Fix in v0.11.0 ships `SubscribeEvents`/`UnsubscribeEvents` (multi-subscriber); `WaitForResponse` uses subscribe pattern internally without displacing external subscribers; `TestSubscribeEventsMultiSubscriber` covers two concurrent subscribers receiving events, with unsubscribe stopping only the unsubscribed one

## Ideas & Innovations

### AST-Aware Three-Way Merge with Per-Language Declaration Algebra ([sawmill](https://github.com/marcelocantos/sawmill))

`git merge` works at the line level: any two edits that touch overlapping lines produce a conflict marker, even when they're structurally orthogonal (parallel method additions, parallel imports, format-vs-logic). Sawmill's v0.12.0 merge engine **aligns base/ours/theirs by `(container, kind, name)` and applies a structural commute table** — `Added + Unchanged → Added`, `Deleted + Unchanged → Deleted`, `Modified + Unchanged → Modified`, with body-level diff3 fallback only for true `Modified + Modified` on the same declaration. Whitespace-normalised fingerprints make identity tests cheap. Format-vs-logic specifically is preserved: if one side reformats and the other side adds a method, both changes land. The `git mergetool` driver and the `merge.driver` per-attribute integration mean this is a turn-on for any repo: `*.go merge=sawmill` in `.gitattributes`, `git config merge.sawmill.driver "sawmill merge-driver %O %A %B %P"`, and three-way merges silently resolve structural orthogonality without conflict markers.

### Bullseye Auto-Commits Its Own State ([bullseye](https://github.com/marcelocantos/bullseye))

Bullseye targets are convergence anchors: each session typically mutates the YAML several times (raise a target, retire one, set one aside, fork). The `/cv` skill used to run a post-mutation `git commit bullseye.yaml` to keep the tree clean before invariants-check. v0.25.0 moves that responsibility **inside the bullseye binary**: after every mutating tool call (`bullseye_put`, `bullseye_retire`, `bullseye_set_aside`, `bullseye_rework`, `bullseye_init`, `bullseye_import`) and at the start of `bullseye_convergence`, bullseye decides whether to fold the dirty file into the previous unpushed `Update bullseye.yaml` commit (via `git commit --amend --no-edit`) or create a fresh one. Best-effort with non-fatal git failures; silent no-op outside a git repo. The MCP server is now self-housekeeping. The decision tree (clean-vs-dirty × HEAD-shape × push-state) is small but covers every scenario: a fresh mutation amends the previous bullseye-only commit if it exists; otherwise it creates one; other staged changes are left alone; pushed commits are never amended.

### Pre-Mutation Tunnel Warnings ([bullseye](https://github.com/marcelocantos/bullseye))

Tunnels (orphaned targets with no checkpoint between them and the root) are the most common form of bullseye-graph rot. The previous flow: tunnel exists → next `/cv` discovers it three operations later → user has to recover context to remember why this target was raised. v0.24.0 moves detection to the source: every `bullseye_put`/`bullseye_retire`/`bullseye_set_aside` runs the post-mutation graph through tunnel detection and appends a warning section listing each orphaned target with **distance-to-checkpoint and ranked checkpoint candidates** (convergence nodes first, then roots, then the orphan itself, then mid-chain on-path nodes). Mutations succeed regardless — it's informational. The agent reads the warning, decides which node to elevate to `kind: Verify`, and flips it in a follow-up put. The same machinery is now public (`graph::suggest_checkpoint_candidates`, `graph::format_tunnel_warnings`) so skills and future tools can reuse it. The pattern generalises — any structural invariant on a graph-shaped state can attach as a post-mutation warning that doesn't reject but informs.

### Demand-Only Pool with Adopt-from-Live + SQLite Hold Ledger ([spyder](https://github.com/marcelocantos/spyder))

The previous pool was eager: at startup, `Reconcile()` minted up to `AvailableMin` sims per template and pre-booted up to `RunningWarm` of them; `AvailableMax` evicted just-released sims when full. Net effect: the daemon pre-emptively spun up sims nobody had asked for, and the cap-on-release behaviour penalised the most-recently-used sim instead of the oldest. Worse, the empty in-memory inventory at startup orphaned the previous run's pool, and `Reconcile` ignored `TierReserved` so an active reservation caused permanent overshoot. v0.28.0 + v0.29.0 redesign: **`Adopt()` rebuilds inventory at startup from live `SimList`/`AVDList` filtered to `spyder-pool-*`**, cross-referenced with a SQLite hold ledger (`modernc.org/sqlite`, pure-Go) that survives daemon restarts; `Acquire(template, holder)` persists holds; `Release` and destroy clean up. `Reconcile` (still callable for explicit warming via `pool_warm`) now counts available + running + reserved toward the floor. Then v0.29.0 drops `AvailableMin` and `RunningWarm` from active behaviour entirely: `Acquire()` is the only mint path; `AvailableMax` governs LRU-on-release eviction (oldest by `LastReleaseAt`/`CreatedAt` first); `pool_gc` MCP tool deletes orphaned `spyder-pool-*` sims/AVDs the daemon doesn't track (booted orphans skipped to avoid yanking sims from unrelated tools). Simulator pools across daemon restarts are now stable and predictable.

### Multi-Client Mux Relay with Per-Client Tag ([pigeon](https://github.com/marcelocantos/pigeon))

The previous pigeon API was 1:1 — one backend, one client, one paired session. To support N clients on one backend (jevon car-mounted iPad + desktop dev session against the same jevons daemon), v0.21.0 lands the multi-channel API: `pigeon.Register` returns a `*Listener`; `Listener.Accept` yields one `*Session` per paired client; per-client routing happens via a 4-byte `clientTag` prepended to every backend-bound stream and datagram. Pairing's 1:1 path is preserved via a `register` vs `register-mux` handshake variant, so an existing 1:1 backend doesn't need to opt into mux. Within a session, `Session.OpenStream(ctx, name)` opens fresh QUIC streams (length-prefixed name as first message), and `Session.Datagram(name)` returns a pre-declared channel framed as `AEAD([varint id][payload])` with the channel id inside the AEAD envelope so a tampered channel-id field is detectable. `crypto.Channel` is now safe under concurrent use (atomic nonce allocation, mutex-guarded `Decrypt`). The visual web demo (`make demo --clients=N`) makes this property literally visible — N animated client cards routing through one backend, with the relay pulse taking each client's accent colour as it speaks.

### QUIC Transport Built on ngtcp2 + PicoTLS Minicrypto ([csp](https://github.com/marcelocantos/csp))

QUIC support in csp had been a frontier target for months. v0.13.0 lands it as `csp::quic::listen`/`dial` over [ngtcp2](https://github.com/ngtcp2/ngtcp2) with [PicoTLS](https://github.com/h2o/picotls) minicrypto as the crypto adapter (vendored as a 709-line C file). The structurally interesting parts: **`stream_pair` uses an unbuffered inbound channel** to avoid a buffered-filter race where the filter delivered empty bytes when the writer closed before the reader was in scope; **path.local fixed on client** (bound address, not peer address) so the connection ID lookups land on the right table; **relay imp for outbound data uses a mutex-protected queue + wake pipe** rather than a busy-loop. Three tests (echo-single-stream, multiple-streams, listener-drop) cover the basic acceptor + initiator + drop-mid-stream paths. The Linux fix (`EPOLL_CTL_MOD` to re-arm one-shot UDP fd events) was a kqueue-vs-epoll asymmetry: macOS auto-rearms; Linux doesn't. Two tests skipped on Linux during development came back online after the rearm landed.

### CSP Amalgamation Hits the C99-vs-C++ Wall ([csp](https://github.com/marcelocantos/csp))

The `dist/csp.cpp` story has worked: a single-TU C++ amalgamation lets users vendor csp via a single file. The protocols (HTTP/1.1, HTTP/2, HTTP/3, WebSocket, QUIC) live in five `.cc` files with vendored C deps (llhttp, nghttp2, nghttp3, ngtcp2, wslay) — naturally a candidate for the same treatment. The amalgamation infrastructure landed: DFS sibling-header inlining with guard preservation, per-file static-name collision detection + `#define` renaming, per-file C-source patch hooks, sfparse cross-include skip, ngtcp2/nghttp2/nghttp3 `version.h` auto-generation from `.in`, vendored-source feature flags, `extern "C"` wrapping. The 117 K-line `dist/csp_net.cpp` *generates*, but **does not compile**: ~623 hard errors on `clang -std=c++20 -stdlib=libc++` (370 implicit `void*` → typed pointer in malloc/calloc sites, 125 cascading guard collisions, 28 conflicting forward decls across .c files, 10 implicit `int` → enum). The original paper assumed `extern "C"` would suffice — but **`extern "C"` controls linkage, not parsing**; Clang has no language-switching pragma to compile sections of a `.cpp` TU as C99. Design paper 21 documents the wall and four resolution paths (per-file `gcc/clang` C-mode compile + link; per-file C extension preserved; transpile C99 to C++23-compatible; rewrite the offending vendored C). Implementer recommendation: revisit the "single .cpp TU, no separate .c files" constraint. The infrastructure remains useful for whichever resolution path is chosen.

### Bullseye Validate Split: Blocking vs Warnings ([bullseye](https://github.com/marcelocantos/bullseye))

`/cv` on pigeon emitted `## Active targets by group` but no `## Frontier`. Diagnosis: `graph::summary` was calling `validate()` (the warning-inclusive path) and stranding the inline frontier section because four T34a/b ID-format advisories tripped the warning gate. The previous report's v0.23.0 had already split `validate()` into `validate_blocking()` (cycles, undefined references) and `validate_warnings()` (quality nudges). v0.26.0 fixes the last caller: `summary()` now gates `## Frontier` on `validate_blocking()` only, while `## Validation warnings` still renders separately so warnings stay visible without doubling as errors. ### Mcpbridge Cycle-Aware Replay Semantics ([mcpbridge](https://github.com/marcelocantos/mcpbridge))

When the upstream HTTP MCP server restarts autonomously, mcpbridge has to re-handshake transparently to the agent. The naive replay strategy (just re-send everything queued) violates **at-most-once delivery semantics for side-effecting tool calls**: a `tools/call` that mutated state twice is wrong, even if the wrapper never returned an error. v0.7.0 splits the replay path: idempotent reads (`tools/list`, `resources/read`, `ping`) replay transparently — they're safe to repeat. Side-effecting `tools/call` requests get a structured `-32002` error so the agent decides whether to retry. Cycle entry/exit are bookended in operator logs (`upstream: cycling — session stale` / `upstream: cycling — complete`) so post-mortems can correlate the stale-detect with the replay landing. The agent's contract is: "you might see -32002 on a tools/call you sent; the call did not happen; retry or escalate."
