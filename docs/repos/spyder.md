# [marcelocantos/spyder](https://github.com/marcelocantos/spyder)

spyder is the Go MCP server and daemon that orchestrates the mobile device fleet — iOS and Android inventory, reservations, app lifecycle, logs, streaming and agent-drivable automation. It is now the sole control plane for the [ge](ge.md) game stack, and drives native devices, simulators, desktop processes and a browser glass through one command-stream protocol.

## The journey

spyder started on Friday 17 April 2026 and reached v0.5.0 by the Sunday — 65 commits, 206 files, +18,790/-649, five releases in three days. The first cut established the shape it kept: an HTTP MCP server (the mcpbridge stdio-proxy approach was dropped immediately) with a platform-adapter split — iOS through pymobiledevice3 and CoreDevice, picking up where mobile-mcp's WDA path fails; Android through `adb` and `dumpsys` — plus a reservation system with canonical UDID normalisation so parallel agent sessions could not yank each other's devices. Seven mobile-development primitives landed in a single fan-out: orientation, screen recording, crash collection, install/deploy, network shaping, simulator and emulator lifecycle, log tailing, and a run-artefact store under `~/.spyder/runs/`.

The next month was the **Python bridge era and its refutation**. The iOS power-assertion path originally used a sideloaded KeepAwake companion app; ten releases (v0.10.0 → v0.19.0) replaced it with a PyInstaller-bundled FastAPI `pmd3-bridge` over a Unix domain socket, supervised by a Go subprocess manager. Eleven more (v0.20.0 → v0.30.0) hardened that bridge: a recoverable-versus-fatal transport-error split ended a daemon panic every ~30 minutes that had been booting Claude Code clients off MCP; iOS log streaming moved onto the bridge to escape the launchd `PATH` trap; autoawake grew a user-opt-out state machine; and the simulator pool was rebuilt demand-only with a SQLite hold ledger, adopt-from-live inventory and `pool_gc`. Then the whole edifice was deleted. When `go-ios` crossed the capability bar, T56 removed pmd3-bridge, pmd3-tunneld and the per-call `xcrun devicectl` shell-out outright — 6,151 lines of bridge code and tests gone, **net −12,592/+2,725 across 122 files** — replaced by a 166-line session helper amortising the RSD handshake behind a ~60 s cache. The report's reading was that the volume of supervision the bridge required *was* the signal the architecture was wrong.

Hardening followed deletion. v0.35.0–v0.48.0 taught the userspace tunnel to **self-heal when a device's RSD lifeline dies** — tearing down and re-establishing only the affected tunnel rather than restarting the daemon — consuming a fix landed upstream in `go-ios`; managed log-capture sessions arrived with a `math/big`-free oslog parser, the autoawake/KeepAwake supervisor was ripped out, usbmuxd wedges gained auto-recovery, and a `spyder doctor` plus an observability pass made failures legible. An in-flight devicectl/CoreDevice migration was set aside rather than merged: the scoped self-heal had made the wholesale adapter rewrite unnecessary.

From June the work turned outward, toward apps rather than devices. `log_collect_*` made spyder a per-session TCP log listener with **port-per-session as the identity boundary** — the socket, not the payload, identifies the sender. v0.52.0 then shipped the bidirectional MessagePack-RPC channel server that ge's `appchannel` dials (JSON-RPC envelopes over 16 MB-capped length-prefixed frames, 32 new tests, +3,113 Go lines), and by v0.58.0 the app-channel had absorbed logging entirely and `log_collect_*` was retired. In parallel, v0.54.0 reached *beneath* the modern stack: deploy, launch and screenshot for **iOS ≤16 over the lockdown protocol with no tunneld**, restoring a whole class of older test hardware that the `devicectl` gate had been silently filtering out. The agent surface then collapsed: T88 replaced the one-off MCP tools with `app_exec`, a hermetic Starlark sandbox running an agent-supplied script server-side with every spyder verb as a builtin and a shared handler map guaranteeing MCP/Starlark parity by construction.

July made spyder the only control plane. **"Plateau P"** re-implemented every ged capability — tweaks, logs, state, screenshot, H.264 streaming — on spyder's app-channel across four launch media (device, simulator/emulator, desktop, server-spawned instance), proved the streaming path end-to-end in headless Chrome, and only then let [ge](ge.md) delete the entire `ged/` daemon and React console (−12,630 lines). The following week the glass itself became location-transparent: the same C++ player tree compiled to wasm and served at `/player/`, replaying SP2S at ~55–60 fps in Chrome, WebKit and Firefox, alongside a headless scripted glass, a six-state daemon/device health plane with recovery-exhaustion escalation, and durable host Starlark explore/collect/regress recipes. The most recent cut is semantic: `hit_targets` addresses UI **by stable id, then role, and deliberately never by display label**, failing closed on a disabled target, and `app_metrics_*` proxies ge's zero-I/O per-instance frame-metrics ring so an agent can pull full retained frame history instead of latest-value gauges.

## Standouts

- **A daemon that panicked every thirty minutes** — the autoawake supervisor polled the pmd3-bridge every 2 s; one wedged bridge tripped a 10 s deadline and panicked the process, and `KeepAlive=true` respawned it, so every Claude Code client saw a hard MCP disconnect twice an hour. The heartbeat fix was real but useless against a dying process; the cure was splitting recoverable transport errors from genuine bugs. ([2026-05-03](../../reports/weekly-report-2026-05-03.md))
- **Deleting 12,000 lines because a library caught up** — the whole PyInstaller/FastAPI bridge existed only because Go's iOS-control story was inadequate. When `go-ios` crossed the bar, T56 removed pmd3-bridge, pmd3-tunneld and the `xcrun devicectl` shell-out in one PR (net −12,592/+2,725 across 122 files), replaced by a 166-line session helper. The volume of supervision the bridge demanded *was* the evidence the architecture was wrong. ([2026-05-10](../../reports/weekly-report-2026-05-10.md))
- **Identity is the socket, not the payload** — log collection normally needs in-band tagging and an app-side parsing contract. `log_collect_*` opens a fresh kernel-assigned TCP port per session and hands it to the app, so a connection arriving on that port is unambiguously from the app launched against it. ([2026-06-07](../../reports/weekly-report-2026-06-07.md))
- **wasm32 shift-width UB in the command-stream hash** — `HashKeyHash` put and get compiled to divergent bucket hashes on wasm32 at `-O2`, so every blob lookup missed and the browser player's first frame never decoded; fixed by pinning the 32-bit shift contract. ([2026-07-19](../../reports/weekly-report-2026-07-19.md))
- **`postRun` is not exit under Asyncify** — with ASYNCIFY, `main()` suspends at its first yield, so `postRun` fires seconds after startup; the player treated that as termination and reloaded healthy sessions on a 1/2/4/8 s backoff. Moving the reload trigger to `onExit` ended the flicker. ([2026-07-19](../../reports/weekly-report-2026-07-19.md))
- **Addressing UI by identity, never by label** — `hit_targets` resolves by stable id, then role, and refuses to match the display label at all, saying so in the error rather than leaving it as folklore; `setHitRect` derives the interaction rectangle and the exported bounds from one value so they cannot drift, and a disabled target is an error rather than a tap into the void. ([2026-07-26](../../reports/weekly-report-2026-07-26.md))
