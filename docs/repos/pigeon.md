# [marcelocantos/pigeon](https://github.com/marcelocantos/pigeon)

pigeon is an end-to-end-encrypted relay and transport library that connects devices when the backend sits behind a private network with no ingress. It carries AEAD channels over raw QUIC and WebTransport, derives its pairing ceremony and session state machines by codegen from YAML specifications into Go, C, Swift, Kotlin, TypeScript, TLA+, and PlantUML, and authenticates pairing with a ZRTP-style commit-reveal short authentication string.

## The journey

The project entered the series as **tern**, extracted from jevon (now [jevons](jevons.md)) into a standalone library in a forty-two-commit opening week. The core is a Go WebTransport relay on quic-go, deployed to Fly.io with automatic Let's Encrypt TLS via certmagic, carrying both reliable streams and unreliable datagrams. Around it sat a `Conn` abstraction spanning WebSocket relay, WebTransport relay, and direct LAN — with **automatic upgrade from relay to LAN** once both peers detect same-network reachability, invisible to the application because the E2E layer sits above the transport and needs no re-keying. Encryption was X25519 ECDH with AES-256-GCM under monotonic counter nonces and directional HKDF-SHA256 derivation, with a six-digit confirmation code for MitM detection. Clients existed for Go, Swift (Network.framework QUIC), Kotlin, and TypeScript, and `protogen` already generated Go, Swift, Kotlin, TypeScript, TLA+, and PlantUML from YAML protocol specs. Seven releases, four audit rounds.

An eighty-seven-commit hardening week followed. Coverage climbed — root package 78% to ~89%, crypto 81% to 91.5%, protocol 75.6% to 97.5% — behind `faultproxy`, a transparent UDP proxy with sequence-aware injection (`DropAfter`, `DropWindow`, `PacketHook`) that exercises the real stack including encryption, fragmentation, and retransmission rather than a mock. Large-datagram fragmentation and reassembly folded into `SendDatagram`/`RecvDatagram`, the LAN upgrade was redesigned around a standalone `LANServer`, and five audit rounds closed with all findings fixed.

Then the **rename to pigeon**, and with it a protocol redesign. The whole session protocol — pairing ceremony and transport session together — was specified in a single 784-line YAML file with phases, typed variables, struct definitions, adversary guards, and fairness and liveness properties, from which typed state machines were generated for Go, Swift, Kotlin, and TypeScript; state machines mediate all `Conn` I/O so application code never touches raw protocol messages. The TLA+ generator was rewritten from PlusCal to pure TLA+ with constant promotion, phase-scoped transitions, and channel elimination, collapsing the state space to 121 states verified in under a second — fast enough to run in CI. A pure C client followed: zero-allocation and struct-based, with X25519, ChaCha20-Poly1305, and HKDF, an amalgamated two-file `dist/` distribution with a CI staleness check, and Go-generated crypto test vectors that each client language validates locally without network dependencies.

The next phase pushed formal verification into the transport and widened the client matrix. A TLA+ `CutoverProtocol` model verified across **159K states** proved that a single CUTOVER marker plus a bounded receiver drain window gives bounded-loss path cutover with no sequence numbering — roughly 200 lines of Go instead of a full ordering state machine. ngtcp2, quictls/openssl, and nghttp3 were vendored as submodules under `c/vendor/` behind a `pigeon_ngtcp2_transport` vtable over raw QUIC with zero heap allocations in pigeon code. A one-time-token race closed by consuming the token at `pair_hello` acceptance rather than ceremony completion, and the relay moved from a single `occupied` flag to a client counter supporting N independent bridges per instance. Typed pairing primitives — `PairingArtifact`, `CredentialStore`, `PairingHost` — then obsoleted jevons' bespoke X25519 and ad-hoc QR JSON, with `cmd/pigeon-pair` folded into a `pigeon pair` subcommand emitting text, JSON, or QR.

Multi-client came next. v0.21.0 replaced the 1:1 API: `pigeon.Register` returns a `*Listener`, `Listener.Accept` yields a `*Session` per paired client, `Session.OpenStream` opens named QUIC streams, and `Session.Datagram` returns a pre-declared channel framed as `AEAD([varint id][payload])` with the channel id inside the AEAD envelope so tampering is detectable. A four-byte `clientTag` routes every backend-bound stream and datagram, and the 1:1 path survives through a `register` versus `register-mux` handshake variant. Wire formats were then lifted out of four parallel `sprintf` branches into `protocol/wireformats.yaml` and codegenned into every language target — the only prior way to verify the branches agreed on byte format was to read all four side by side. Around it landed C pairing and activation drivers with byte-for-byte Go wire-parity tests, the deletion of the legacy `pigeon.Conn`, libsodium vendored as a pinned submodule for every consumer, and a seven-target cross-language fan-out covering Keychain-backed identity, a Swift ceremony driver, Go↔C interop through a Go relay, an Android NDK build matrix, a JVM-callback transport, a real ngtcp2 QUIC transport for Swift, and a Unix-socket local backchannel. Authentication was subsequently inverted from a hard-wired bearer check into a func-valued `Auth` struct seeing the live connection, TLS state, and greeting, with `BearerTokenAuth` and `MutualTLSAuth` as bundled defaults; a JNI Kwik transport gave Kotlin real QUIC; and 🎯T45 collapsed the relay to a remote-Listen model (`register`/`listen`/`connect`, per-client QUIC pipes) in a net −1,363-line API rewrite.

The final phase is security. v0.25.0 let one `PairingRecord` fan out to concurrent services via a fresh sixteen-byte per-session nonce in the HKDF, `Route` sub-addressing carried inside the end-to-end AEAD so the relay never learns the service, and an `enumerate` RPC over a reserved discovery stream. The Fable-5 audit then confirmed eight of nine critical and high findings, including a **non-atomic `send_seq++` nonce-reuse race** — the production channel counter was shared across every stream pump and the datagram pump and advanced by a non-atomic C read-modify-write, so 16,384 concurrent encrypts produced 1,964 colliding nonce prefixes, a race living in C and therefore invisible to Go's race detector — plus deterministic keys from a static pairing record with a counter reset, and a ~19.9-bit SAS with no commit-reveal that a relay MitM could grind. Six releases, v0.26→v0.31, remediated all of it: the counter serialised, then structurally forked so every named stream and the datagram path gets its own AEAD channel derived via HKDF diversify labels and can never share a sequence space; a ZRTP-style commit-reveal SAS round that ends the MitM grind (previously 305,883 tries in 3.2 seconds); per-session salt on artifact reconnect; automatic LAN upgrade; deterministic ceremony teardown; progressive datagram fragmentation; and a hub-ID ownership fix. Each shipped a failing-then-passing reproduction under `-race`, alongside two method essays on formal state machines and adversarial modelling.

## Standouts

- **A confirmed AES-GCM nonce-reuse race** — the production channel counter was shared across every stream pump and the datagram pump and advanced by a non-atomic C read-modify-write, so 16,384 concurrent encrypts produced 1,964 colliding nonce prefixes; the race lived in C and was therefore invisible to Go's race detector, needing a keystream-uniqueness oracle to catch and a structural per-flow AEAD fork via HKDF to make unrepresentable. ([07-12](../../reports/weekly-report-2026-07-12.md))
- **A short authentication string a relay could grind** — the ~19.9-bit SAS had no commit-reveal, so a MitM relay could search it 305,883 times in 3.2 seconds after seeing the peer's public key; a ZRTP-style commit-before-reveal round ends the grind by fixing the attacker's choice before the material it would search on exists. ([07-12](../../reports/weekly-report-2026-07-12.md))
- **Path cutover proved correct without sequence numbers** — a TLA+ `CutoverProtocol` model verified across 159K states showed that one CUTOVER marker plus a bounded receiver drain window gives bounded-loss switching, replacing a full ordering state machine with roughly 200 lines of Go. ([04-19](../../reports/weekly-report-2026-04-19.md))
- **A state space collapsed from intractable to 121 states** — rewriting the TLA+ generator from PlusCal to pure TLA+ with constant promotion, phase-scoped transitions, and channel elimination made the session-protocol model check in under a second, which is what let formal verification run in CI on every change rather than as an occasional ceremony. ([04-05](../../reports/weekly-report-2026-04-05.md))
- **faultproxy** — a transparent UDP proxy with sequence-aware injection (`DropAfter`, `DropWindow`, `PacketHook`) that exercises the real stack including encryption, fragmentation, and retransmission rather than a mock, carrying protocol coverage from 75.6% to 97.5%. ([03-29](../../reports/weekly-report-2026-03-29.md))
