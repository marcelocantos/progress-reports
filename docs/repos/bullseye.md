# [marcelocantos/bullseye](https://github.com/marcelocantos/bullseye)

bullseye is the Rust MCP server that holds the fleet's convergence targets — a git-tracked intent ledger in `bullseye.yaml`, queried and mutated through a four-tool agent API, with portfolio-level ranking across repositories, release and ownership governance, and a one-way mirror into GitHub issues. It started as `targets`.

## The journey

It began at the end of March 2026 as **targets**: a Rust MCP server with a hierarchical YAML schema carrying status and WSJF ranking fields, a `targets_render` tool that auto-rendered on mutation, frontier-based scheduling, and a design document modelling the target lifecycle as a hierarchical state machine. A week later it grew the apparatus that would define — and eventually be dismantled by — its next three months: verification targets with a `kind` field and `verifies` edges, bounded rework loops with retry budgets, and tunnel detection for work targets sitting too far from their verification gate.

Renamed **bullseye**, it then had its biggest week of the series: 75 commits and ten releases (v0.5.0 → v0.14.0) taking it to production maturity. `bullseye_convergence` added gap analysis, `bullseye_portfolio` computed cross-repo WSJF over cross-repo dependency edges so a target in one repository could depend on one in another, acceptance checks became executable through [sawmill](sawmill.md), `bullseye_assert` was renamed `bullseye_put`, schema-version enforcement arrived with the hardening every speculative call path needed to survive a broken file, and the fleet-wide `targets.yaml` → `bullseye.yaml` rename swept 40+ repositories. Storage location took two attempts: v0.15.0 shipped a machine-wide config selecting in-repo versus external storage, and **v0.16.0 threw it away three hours later** — location is a per-repo property encoded by where the file physically lives, discovered by in-repo walk-up then shadow walk-up, with no machine state at all.

Late April brought rigour rather than features: a `set_aside` status with a schema-enforced rationale for targets that are wrong but should not vanish without a record; the lockfile moved out of the project directory and keyed by parent inode so concurrent runs across sibling worktrees stop colliding; structured `sawmill_failure` and `mnemo_history` payloads on the rework flow; an **envelope-leak guard** machine-checking every target's value/cost envelope against its parent's, with acceptance tests for each failure mode; and a `validate_blocking`/`validate_warnings` split so quality nudges stopped suppressing frontier output. A SQLite `targets_priorities` writer let downstream consumers — [jevons](jevons.md)'s active-work dashboard, `/cv` scoring — read priorities without re-parsing every project's YAML. bullseye then became self-housekeeping: tunnel warnings are appended to every successful mutation with distance-to-checkpoint and ranked checkpoint candidates, and a dirty `bullseye.yaml` is folded into git *by bullseye itself* after every mutating call, amending the previous unpushed ledger commit where one exists.

May's theme was **substrate minimisation**, two schema simplifications in as many weeks. v0.27.0 removed the showcase construct entirely (schema 3 → 4, with permissive deserialisation so legacy keys load once and disappear on save) and refused mutation inside submodule replicas or under detached HEAD. v0.28.0 then removed the `kind` enum and everything that had grown around `kind: verify` — `verifies` and `rework` edges, retry budgets, `is_checkpoint`, checkpoint distance, tunnel detection, two MCP tools — on the reading that **shape is a property of subgraphs, not nodes**; frontier ordering became max unblocking fanout (the frontier is the parallelisable set, so agents fan out rather than pick), failed retirement got `bullseye_revert(id, reason)`, and the diff was 524 added against 2,583 removed. The stated ambition was that bullseye-the-tool should be a minimal substrate like Make, with the leverage carried by bullseye-the-practice.

Through June the surface widened again, carefully. `bullseye_subdivide` decomposed a target in one call; a **git-history ID allocator** derived the next target ID from the union of everything any branch had ever assigned, so parallel worktrees can no longer mint the same id; five releases added a GitHub issue mirror via `bullseye github sync` — a one-way projection that leaves `bullseye.yaml` the single source of truth, so there is no bidirectional-sync ambiguity — along with CLI/MCP surface parity, a shape vocabulary with tail-aware subdivide, release-freeze-aware resolution and a self-documenting file header; and v0.36.0 fixed an invariants-hook timeout that had been hanging esfera2's target validation outright. July collapsed the agent surface to a **four-tool ledger API** (`bullseye_open`, `bullseye_query`, `bullseye_commit`, `bullseye_plan_checks`, legacy tools demoted to shims) with structured envelopes and stable error codes, added `release_surface` and `owned_by` governance and server-minted child IDs closing a TOCTOU in allocation — a release whose +32,938 lines are mostly a vendored `rust-mcp-sdk` (~29.5k; authored Rust ≈2.5–3k). Most recently it grew a feature-gated issuepipe consumer with a continuous poller, mapping issues to targets with authorisation and consent kept separate, skipping a forbidden repository without aborting the cycle, and measuring **4 seconds end-to-end pickup**. Auto-commit after every mutation — the source of yaml-only chatter — was then **stopped** (v0.46.0): mutations write the file and leave it dirty; `/commit` stages; `/push` refuses. The T72 amend path is deleted. Dotted child IDs are umbrella `depends_on` edges so a family cannot retire while children are open. Standing-invariants dirty tree warns instead of failing `make bullseye`.

## Highlights

- **Ten releases and portfolio convergence** — 75 commits taking v0.5.0 to v0.14.0: cross-repo WSJF with cross-repo dependency edges, executable acceptance checks via sawmill, and the `bullseye.yaml` rename across 40+ repos. ([2026-04-12](../../reports/weekly-report-2026-04-12.md))
- **Storage location redesigned three hours after shipping** — the machine-wide config is deleted in favour of per-repo, path-driven discovery with no machine state. ([2026-04-19](../../reports/weekly-report-2026-04-19.md))
- **Rigour: set-aside, envelope guard, validate split** — six releases adding a rationale-bearing third life-state, machine-checked value/cost envelopes, and a blocking-versus-advisory validation split. ([2026-04-26](../../reports/weekly-report-2026-04-26.md))
- **Showcase removed, mutation refused in replicas** — schema 3 → 4 with one-shot migration, plus a guard against mutating inside a submodule replica or detached HEAD. ([2026-05-10](../../reports/weekly-report-2026-05-10.md))
- **Schema v5: the `kind` enum removed** — 524 lines added against 2,583 removed as verify-vs-work node typing gives way to max-unblocking-fanout frontier ordering and `bullseye_revert`. ([2026-05-17](../../reports/weekly-report-2026-05-17.md))
- **Target IDs allocated from git history** — the namespace is reconstructed from history, so parallel worktrees and agents never mint the same id twice. ([2026-06-14](../../reports/weekly-report-2026-06-14.md))
- **GitHub issue mirror and CLI/MCP parity** — targets projected one-way into issues so collaborators meet the graph where they already look, without surrendering the authoritative store. ([2026-06-21](../../reports/weekly-report-2026-06-21.md))
- **Four-tool ledger API with governance** — the surface collapses to open/query/commit/plan_checks with structured envelopes, plus release-surface and ownership rules and TOCTOU-safe server-minted IDs. ([2026-07-12](../../reports/weekly-report-2026-07-12.md))
- **Issues as a target event path** — a feature-gated issuepipe consumer with strict opt-in, existence-non-disclosure on 403 and 4-second measured pickup. ([2026-07-26](../../reports/weekly-report-2026-07-26.md))
- **Attestation on achieve, and graph hygiene** — closing a target now requires a free-text note on how it was met (trivial tokens rejected), alongside a content-hashed store, postpone/wake gating, and advisory merge-completeness for multi-predecessor fan-in (v0.40 → v0.44). ([2026-08-02](../../reports/weekly-report-2026-08-02.md))
- **v0.45.0: UTF-8 hang, bounded subprocesses, ledger SHA stability** — non-UTF-8 subprocess output no longer hangs the server; amend ownership is a process-local HEAD record so concurrent agents cannot orphan each other's cited SHAs. ([2026-08-16](../../reports/weekly-report-2026-08-16.md))
- **Mutations write, they do not commit** — v0.46.0 leaves the ledger dirty; dotted children are umbrellas so a family cannot retire while children are open. ([2026-08-23](../../reports/weekly-report-2026-08-23.md))

## Standouts

- **A design rethrown three hours after it shipped** — v0.15.0 added a machine-wide config plus `bullseye_configure` to pick in-repo or external storage, which muddled "where does bullseye live?" with machine state. v0.16.0 deleted it for path-driven probing: in-repo walk-up first, then a shadow walk-up under `~/.local/share/bullseye/<abs-cwd>`, so location is a property of where the file physically lives and no machine state exists at all. ([2026-04-19](../../reports/weekly-report-2026-04-19.md))
- **A tool absorbing its own skill's workaround** — `/cv` used to run a post-mutation `git commit bullseye.yaml` to keep the tree clean before the invariants check. v0.25.0 moved that inside the binary; v0.46.0 reversed the auto-commit once yaml-only chatter became the dominant history, leaving durability on `/commit` and `/push`. ([2026-08-23](../../reports/weekly-report-2026-08-23.md))
- **Shape is a property of subgraphs, not nodes** — the `kind` enum encoded verify-versus-work as a node type, baking a particular validation moment into an attribute when those moments emerge from how the surrounding subgraph is structured. Schema v5 removed it along with `verifies`/`rework` edges, `retry_budget` and checkpoint flags — 524 lines added against 2,583 removed. ([2026-05-17](../../reports/weekly-report-2026-05-17.md))
- **Target IDs allocated from git history, not the working file** — a naive "next integer" allocator collides the moment two worktrees both mint 🎯T29. Deriving the next ID from the union of everything any branch has ever assigned means the namespace is reconstructed from history while `bullseye.yaml` stays the source of truth. ([2026-06-14](../../reports/weekly-report-2026-06-14.md))
- **A four-tool surface with the TOCTOU closed** — the API collapsed to `open`/`query`/`commit`/`plan_checks` with structured envelopes and stable error codes, legacy tools demoted to shims; child IDs are minted server-side so no caller can read-then-write into a collision. ([2026-07-12](../../reports/weekly-report-2026-07-12.md))
