# [marcelocantos/jevons](https://github.com/marcelocantos/jevons)

jevons is the fleet cockpit — a Go daemon and web UI for running, watching and governing a fleet of AI coding agents, with a durable Butler/CEO thread model, live token-spend governance and a stranger-safe local install. It began life as `dais`, became `jevon`, and settled on `jevons`.

## The journey

The project was born in March 2026 as **dais**, a multi-session [Claude Code](https://claude.ai/code) orchestrator built on a *shepherd* pattern: users talk to one coordinating session that decides whether to answer directly or delegate to a specialised worker, with WebSocket broadcast to multiple observing TUI clients, SQLite persistence for `--resume` continuity, and a Bubbletea/Glamour terminal client. Within a week it was renamed **jevon**, and the rename came with a rethink — the `workers` database table was replaced by **filesystem-based session discovery** with relevance ranking, eliminating an entire category of stale-record bugs, and the project acquired a formal trust model, a native Swift/SwiftUI iOS client and QR-based server discovery.

An experimental phase followed. The iOS app became a generic renderer for **server-pushed Lua**: the daemon sends scripts over WebSocket and the client, embedding Lua 5.1.5, executes them to construct native SwiftUI views — a 782-line `LuaRuntime.swift` registering 26 builder functions and 15 modifier properties, with `on_tap`/`on_submit` calling back to the server so business logic never leaves it. Alongside it came bidirectional sqlpipe state sync across Go, C and Swift, then `protogen`: YAML protocol specifications compiled to Go, Swift, TLA+ and PlantUML at once, with the PairingCeremony handshake model-checked by TLC after taming state-space explosion by bounding channels and exploiting role symmetry. The relay half of that work was **extracted into a standalone library, `tern`** — later renamed [pigeon](pigeon.md). The end of March brought a Grok Realtime voice bridge (Grok handles voice, Claude handles reasoning) and a desktop-first split-pane web UI with JSONL-backed persistent chat.

April renamed the project a second and final time, to **jevons**, and turned to hardening the perimeter and the cross-repo view. v0.4.0 shipped an Ed25519 mTLS CA with device provisioning and TLS 1.3 client-cert enforcement, a depth-limited recursive `jwork` delegation tool with progress heartbeats, and `jevons_active_work` — an MCP dashboard aggregating recent Claude sessions, dirty working trees and open PRs into one ranked cross-repo table. The bespoke X25519 pairing was then retired in favour of pigeon's typed `PairingArtifact`/`PairingHost`/`CredentialStore` primitives, which also unlocked an env-var deploy path that connects a freshly launched iOS build without a QR scan.

May was **substrate minimisation**. A cleanup sweep absorbed ten minor versions of [claudia](claudia.md) API churn and then deleted things: the entire SQLite database layer, the legacy `jevons` Go package and the embedded Lua interpreter all went, because `transcript` and `raw_log` had only writers — [mnemo](mnemo.md) already indexed the JSONL session files and was the real search and replay layer. **JSONL became the canonical source of truth.** In the same stretch, push-to-talk voice was made robust (manual commit, `CommitAndRespond`, a 30 s idle timer, and a fix for a zombie Grok session that shipped audio into a closed socket), and browser resilience gained exponential-backoff reconnect, heartbeats and version-probe reload. Through late May and June the repo went quiet on master while a `voicelab` desktop CLI accumulated in-flight.

It returned in July as a real cockpit. v0.5.0 introduced the **Butler/CEO thread model** — a thread is a durable transcript plus metadata and the worker process is treated as a *cache* of it, so a stopped or aged worker is transparently resumed — together with an `internal/cost` package born from a live money-loss incident on 6 July: real-time usage tailed from *every* session JSONL regardless of who started it, a burn-rate monitor, and a warn→throttle→pause→kill ladder whose kill-switch reaches the launchd-detached fleet tmux, scoped to fleet-plus-orphan so the owner's own heavy sessions do not trip it. The following week closed a silent failure that had produced weeks of toolless overseer boots — Grok reclassifies ACP `mcpServers` matching a cwd `.mcp.json` as repo-local and drops them without error — with a session-scoped `mcp.claudia.json`, claudia v0.19 attach, and a **toolless-boot oracle that treats zero `tools/list` in 45 s as a loud failure**; the same release made the conversation itself the durable artefact via an fsynced jevons-owned chat log replayed before any liveness check, and added a loopback-only default bind and a `go:embed` web UI so brew installs no longer 404. Most recently the chat UI was made to scale: load on the owner's real 4,707-line history fell from **15–20 s to ~1.5 s** by bounding what the browser materialises — 30-turn server replay with paged history, preview-only rendering, an rAF-debounced coalescer — while leaving the journal untouched, and a decisive experiment falsified the belief that had made a context-destroying session-rotation hack look mandatory.

By August the cockpit had become the thing doing the building. Most of a 297-commit fortnight's jevons work was landed by jevons's own supervised fleet, and the failures that followed were **coordination** failures rather than coding ones: workers sharing one clone silently reverting each other's edits, a bare `git commit` sweeping a neighbour's staged changes into someone else's tree, and an auto-reap destroying an agent because the word "complete" appeared inside "incomplete". Each fix is a guard rather than a convention — a compare-and-swap on file writes that names the lines a stale write would drop, a pre-commit gate keyed on `GIT_INDEX_FILE`, and a reap that vetoes itself when a report asks a question. In parallel, fleet **economics** became an engineering surface: spend decomposed as turns × calls-per-turn × context-per-call from the providers' own billing frames, a hard context ceiling in which an unknown measurement never triggers compaction, wake coalescing after a breakdown showed over half the most expensive agent's prompts were machine noise, and capacity-aware admission giving the ambient research, audit and coach cycles one shared view of pressure.

The next week was survival. Crash-survival without recovery rematerialised a **ghost Claude fleet** until a 128 GB host sat at load 267 with 0.14 GB free — the compressor, not the CPUs. Upgrade now adopts leftover tmux windows; ordinary start does not reap, so an exit leak stays visible; the daemon and a launchd watchdog supervise each other from different process trees after launchd quietly dropped the job. The ceiling, inert on Claude because cached reads were not counted as context, started working and immediately became a treadmill, closed with hysteresis. Plan remaining — a pointer, because 0 is exhausted and nil is unpublished — became the one honest budget a flat subscription has, and host run-queue plus swap folded into admission so a governor cannot report 100% headroom on a drowning machine.

Then the fleet became *interpretable*. Host-owned MCP (claudia loads, probes and proxies; jevons persists tokens), a Session Goal the host can close, Codex Session over `codex app-server`, typed envelopes, and a fog-of-war scout that refuses to implement into an unseen map. Connect-replay pins to the last owner bubble, not the slot tail. The fortnight closed with **React as the daily cockpit** (`:13705`), coalesced transcripts in SQLite, Cursor ACP remint that does not deadlock, an exhausted model that falls down its ladder instead of being re-briefed forever, and the tmux **anchor pane** as the reason the fleet server stays up.

## Standouts

- **A cost monitor that could not see the fleet that was burning** — usage collection watched only *registered* workers while a detached `claudia-anchor` fleet tmux burned tokens off-book. The fix tails every session JSONL on disk regardless of who started it, scopes the kill-switch to fleet-plus-orphan so the owner's own heavy sessions do not trip it, and adds thin-rate and sustained-breach guards so one $11 re-cache message cannot fire the nuke. ([2026-07-12](../../reports/weekly-report-2026-07-12.md))
- **A CLI that silently drops MCP servers in untrusted folders** — Grok's ACP path reclassifies any session-supplied MCP server whose name matches cwd `.mcp.json` as repo-local and discards it with no error, producing weeks of toolless overseer boots. Fixed with a session-scoped `mcp.claudia.json` the CLI does not scan, mint-fresh sessions, and a 45 s toolless-boot oracle that fails loud. ([2026-07-19](../../reports/weekly-report-2026-07-19.md))
- **Bounding what the UI materialises, not what the log stores** — clamping oversized message bodies with CSS made bubbles smaller and changed nothing, because the browser still parsed and built DOM for every turn before hiding it. The real cost was the server replaying the whole journal on each WebSocket reconnect plus an O(N²) streaming coalescer; attacking all three layers took a 4,707-line history from 15–20 s to ~1.5 s with DOM nodes held to ~276. ([2026-07-26](../../reports/weekly-report-2026-07-26.md))
- **The destructive branch was the default under ambiguity** — the fleet's auto-reap fired on any completion word in a terminal report, so a substring test made "incomplete" a claim of "complete". Two of three losses in one afternoon were replies *to* the agent: a reaped agent is not merely gone, it is an unanswerable address, and the caller only learns that afterwards. ([2026-08-09](../../reports/weekly-report-2026-08-09.md))
- **A guard that names what it saved** — treeguard refuses a write whose base no longer matches disk and reports the specific lines it would have dropped, turning silent loss into a mechanical merge instruction; its oracle is two-sided so a guard that refuses everything cannot pass. ([2026-08-09](../../reports/weekly-report-2026-08-09.md))
- **Crash-survival without recovery** — leftover tmux windows rematerialised on every bounce until the host compressor, not the CPUs, stalled a 128 GB machine at load 267; upgrade adopts, ordinary start leaves the leak visible. ([2026-08-16](../../reports/weekly-report-2026-08-16.md))
- **Connect must pin to a person, not a slot** — reload that pins to the slot tail paints a desert of empty turn-slots; J19 fails on an empty pane, not only a collapsed model. ([2026-08-23](../../reports/weekly-report-2026-08-23.md))
- **The anchor pane holds the tmux server open** — `new-window: no server running` while the fleet's own panes were alive; the socket was never wrong, the session that holds it had been reaped. ([2026-08-30](../../reports/weekly-report-2026-08-30.md))
