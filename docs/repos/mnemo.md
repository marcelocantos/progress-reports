# [marcelocantos/mnemo](https://github.com/marcelocantos/mnemo)

mnemo is a Go MCP server that indexes Claude Code session transcripts — and, latterly, Codex and Grok transcripts — into a queryable SQLite spine covering entries, images, documents, commits, PRs, CI runs, memories, and costs. It runs as an HTTP MCP daemon with a live compaction pipeline, mTLS federation between instances, an in-process plugin system, and a macOS menu-bar navigator.

## The journey

mnemo enters the series already running. Its first dedicated section covers a single week that carried it from v0.4.0 to v0.15.0 across eighty-one commits and eleven new MCP tools: context-source indexing (`mnemo_skills`, `mnemo_configs`, `mnemo_audit`, `mnemo_targets`, `mnemo_plans`), memory indexing with fuzzy search, token-usage analytics with hourly rate detection, process attribution via `mnemo_who_ran`, permission analysis, GitHub Actions indexing, session liveness detection via `lsof` on the JSONL file, and full-fidelity ingest capturing tool_use, tool_result, and thinking blocks. Session chains arrived here too — the first attempt at stitching `/clear`-bounded transcripts into coherent work spans.

The following week was the largest single effort of its week across the whole fleet: six releases, eighty commits, and a model pivot. Schema v16/v17 added an image pipeline — inline base64 and file-path images ingested, downscaled past 1568px via CatmullRom, described by the Anthropic vision API with surrounding conversation as grounding, OCR'd through `VNRecognizeTextRequest` moved in-process via CGO + ObjC for a 2-5x speedup, and embedded with CLIP for semantic and visual similarity search. v0.18.0 shipped a live compaction lifecycle — a `Watcher` polling live sessions every 30s, per-session goroutines on five-minute tickers, idle reap at ten minutes, driven by a `claudia.Task` LLM caller. Underneath both, the **connection-identity pivot** re-keyed the compactor and restore path around daemon connection identity rather than session IDs, deleting the ingest-time cwd heuristic outright and moving inference to query time behind a `mode` parameter. v0.20.0 then collapsed the stdio proxy and daemon into **a single HTTP MCP daemon** over mark3labs/mcp-go's StreamableHTTP transport, killing the custom JSON-RPC-over-UDS protocol entirely, and v0.21.0 landed native Windows support.

Eleven more minor releases followed, v0.22.0 through v0.32.0. Windows became first-class — an Inno Setup installer with `MSYS_NO_PATHCONV=1` to stop MSYS mangling the `.iss` arguments, ARM64 cross-compilation via `llvm-mingw` on `ubuntu-latest` instead of the paid runner, and a per-user Windows Service registered under `HKCU\Software\mnemo` with a `schtasks /SC ONLOGON` trigger so installation needs no administrator. Federation arrived in v0.29.0: a self-signed ECDSA P-256 endpoint cert, a peer certificate allowlist that skips malformed entries with a warning rather than blocking, and `mnemo print-endpoint` for paste-distribution. Alongside came `mnemo diagnose`, an idempotent indexer keyed on `(session_id, entry_uuid)`, four more tools, and `mnemo_repos` so `/waw` and the active-projects table populate without scanning every tree. Cost tracking landed next in v0.33.0 — session/block grouping, sub-day windows, and Anthropic API-cost reconciliation feeding a single denormalised view consumed by [jevons](jevons.md) and `/cv`.

Mid-May turned to durability. The 🎯T52 path-exclusion registry replaced an earlier fence-protocol sketch with a canonicalised subtree-skip list — `filepath.Abs` plus `filepath.EvalSymlinks`, lazy re-canonicalisation at check time, is-under matching via `filepath.Rel` — registered by `vault_path` at user init before any walker runs, so mnemo never re-ingests its own output. Docs ingest dropped its directory whitelist for a recursive walk from the repo root with stem-based dedup and `content_hash` incremental re-index. Then eight releases, v0.36.0 through v0.43.0, routed every schema change through [sqlift](sqlift.md) under a **strict additive-only policy** — columns and tables may be added, never dropped or narrowed — paired with a pre-migration snapshot and a periodic backup worker, making the store recoverable by construction. The same run dropped [sqldeep](sqldeep.md) dispatch from `Store.Query`, drove the compactor off session activity rather than connections, and swept stale `daemon_connections`.

The compactor then absorbed a long convergence and hardening arc. Compaction was reframed from a 24-hour recency window — which had silently abandoned every historical session — into a desired-state predicate: a session is owed a compaction when it has new substantive messages since its latest compaction cursor, with recency demoted to `ORDER BY` priority and a per-scan cap draining the backlog. Decoupling the scan from the write path exposed a planner mis-choice hidden behind a missing index; a partial covering index cut a candidate scan from roughly thirty minutes to **142 ms** on a real 7,641-session database. A stuck-watcher that cried wolf whenever the daemon was legitimately busy was fixed by treating `last_tick_at` and `last_scan_at` as independent proofs of life. Compaction-failure healing followed — correct JSON framing, deferral of non-payload records, and durable quarantine rather than dropping — alongside a queryable Obsidian-Tasks TODO index, a three-tier test architecture, cross-session agent-to-agent inbox notes, and the elimination of idle-daemon and dashboard CPU burn.

The final phase is reach and hardening. v0.55→v0.59 shipped a macOS menu-bar session navigator with live SSE, Codex CLI transcript ingest from `~/.codex/sessions/`, `mnemo_status` served from one nested sqldeep projection, a drift-proof `mnemo_config` patch allowlist derived from the struct, and Developer-ID signing in the release pipeline. The Fable-5 audit filed two critical and four high findings against it; remediation in v0.60→v0.62 replaced the client-resettable read guard with a dedicated read driver whose `ConnectHook` authorizer denies `ATTACH`/`DETACH` and `query_only`-off, fixed an ingest-durability bug where a `bufio.Scanner` token cap silently dropped oversized lines, and added a session-affinity MCP edge proxy that upgrades mnemo without invalidating live clients, plus a SIGTERM drain ending in `wal_checkpoint(TRUNCATE)`. Grok ACP transcripts joined the spine in the same run. v0.63→v0.68 closed the series with the vault wing MVP (`_mnemo/` namespace, decisions and memories), an in-process plugin system with launch, proxy, facets, signals, and an MCP bridge, and Codex transcript fidelity down to model, usage, and parent chains.

The most recent phase is containment and cost. A summariser that fed transcripts to a headless model obeyed an instruction embedded in one of them and spawned roughly **33,000 subagents over two hours**, and closing that required a fix in [claudia](claudia.md) first, whose Task mode had never applied the tool restrictions its README promised. Alongside it, a token-cost engine was derived from published pricing rather than from an existing tool — the analysis found the tool's only genuinely external input, a public rate card, sits *upstream* of it — and produced four verified defects along the way, including usage rows duplicated enough to over-count by 1.95× to 2.83× with a factor that varies by class. Streaming topic segmentation arrived with a schema that carefully distinguishes containment from correction, FSEvents replaced a recursive kqueue watcher after a vnode-exhaustion incident, and the MCP surface was finally cut from 70 tools to 18 against recorded usage. The Jevons provider peer was then dropped outright — mnemo no longer dials jevonsd; generic `/health` and `/mcp` stay. Query deadlines and reconciler isolation followed, then a compression pass: `entries.raw` compressed, hot fields materialised, readers on `entries_v`, metadata-only migrations no longer snapshot 18.9 GB, and default backups retained dropped from 7 to 1 (~81 GB of copies). The tool surface is now measured in **bytes** (36,667 → 24,917) by generating the schema catalogue from the live database; file-only config with a watcher, because removing `mnemo_config` would otherwise have silently downgraded hot-reload. Multithreaded libzstd is vendored as a cgo amalgamation, not yet wired into the backup worker.

## Standouts

- **A read-only guard the client could switch off** — `mnemo_query` ran arbitrary client SQL behind nothing but a client-resettable `PRAGMA query_only=1`, so `PRAGMA query_only=0; DELETE` wiped the database and `ATTACH DATABASE` read arbitrary files, both reachable over mTLS federation; the fix installs a SQLite authorizer through a dedicated read driver's `ConnectHook`. ([07-05](../../reports/weekly-report-2026-07-05.md))
- **A five-hour compactor silence traced to write-lock scope** — `pollCIForRepo` held `s.rwmu.Lock()` across a `gh run view --log` subprocess, so the compactor's RLock latency ballooned under CI-poll load; logs are now fetched before the lock and each tick runs under `context.WithTimeout`, and the same investigation surfaced the planner mis-choice that a partial covering index cut from ~30 minutes to 142 ms. ([05-31](../../reports/weekly-report-2026-05-31.md))
- **Five tests that rotted for a month behind a fake `now()`** — a misnamed `now()` helper returned the string literal `"2026-04-09T10:00:00Z"` instead of a `time.Now()`-derived value, so five `TestUsage*` cases compiled cleanly and were guaranteed to start failing about a month later; replaced with a per-process `testAnchor` and `nowAt`/`nowDate` helpers. ([05-10](../../reports/weekly-report-2026-05-10.md))
- **Two liveness signals beat one threshold** — the stuck-watcher cried wolf on every scan once the compactor began draining a 7,700-session backlog, because a full-batch scan legitimately ticks for minutes; the insight is that scan cadence and tick cadence are independent proofs of life, and only both going stale means wedged. ([06-07](../../reports/weekly-report-2026-06-07.md))
- **A graceful drain that was dead code** — the shutdown path existed but ran with `context.Background()`, so `brew services restart` hard-killed mnemo mid-request; a real cancelable context now flows from SIGTERM/SIGINT into an ordered, deadline-bounded drain ending in `wal_checkpoint(TRUNCATE)`. ([07-12](../../reports/weekly-report-2026-07-12.md))
- **A schema catalogue that truncated the views it advertised** — `Store.Query` breaks at 100 rows; `sqlite_master` is creation order, so a listing dropped `entries_v` / `messages_v` / `docs_v`; the catalogue paginates on name. ([2026-08-30](../../reports/weekly-report-2026-08-30.md))
