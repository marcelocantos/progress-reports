# [marcelocantos/den](https://github.com/marcelocantos/den)

A C++ universal development-environment manager that consumes the existing Homebrew ecosystem — formulae, bottles and taps — without requiring rebuilds, sharing `/opt/homebrew/Cellar` while adding multi-version coinstallation, named environments and a multi-provider package model. It reached a v1.0.0 release candidate in late June.

## The journey

den began as **rubrew**, a Rust reimplementation of Homebrew, and was renamed within its first week to reflect a broader ambition: not a Ruby-or-Homebrew replacement but a universal development-environment manager. The bootstrap shipped `install`/`list`/`use`/`search`/`info`/`deps`/`cleanup`, Homebrew formula-index consumption, a content-addressed bottle cache, unattended auto-upgrade with maintenance windows, and the architectural commitment that would define the project — consume the existing ecosystem rather than fork it.

The following week the whole thing was **rewritten from Rust to C++** in 92 commits, onto spdlog, nlohmann/json, libarchive and libcurl, with an independent package store at `~/.den/` and a unified package model across taps. Five adversarial audit rounds turned up over a hundred findings — slug decode corruption, symlink path traversal, hardlink and absolute-path tar extraction, settings reset via config corruption, non-atomic launchd plist writes — and the fixes shipped alongside a wide feature surface (`uninstall`, `upgrade`, `cask`, `services`, a seven-check `doctor`, `migrate`, a background maintenance daemon, shell integration) across v0.1.0 through v0.3.0.

Spring was spent removing Ruby from the critical path. Source builds arrived first, parsing Homebrew formulae to extract configure/make/install steps; an embedded Ruby VM was wired in and then dropped in favour of subprocess invocation against a bundled Ruby binary. The **native C++ formula parser** replaced Ruby evaluation entirely, and its design posture is the interesting part: it **refuses unknown constructs** — unresolvable `#{...}` interpolations, unrecognised DSL methods — rather than silently skipping them, with a golden-file oracle comparing native output against the Ruby reference across the homebrew-core corpus so any divergence surfaces immediately. The same window pointed the store at `/opt/homebrew/Cellar` to share installations with Homebrew, eliminated `brew cat` in favour of fetching formula source directly from GitHub, added `den log` and `den self-update`, retired fifteen targets and cut seven releases (v0.4.0 through v0.10.0).

After a month dormant, den returned in mid-May with verification infrastructure first: 🎯T59–T72 verify harnesses running a documented confirmed-SIMPLE package subset on macOS-14 and ubuntu-latest under GitHub Actions, `docs/targets.yaml` standardised to `bullseye.yaml`, and 🎯T23 decomposed before implementation. The payoff landed in v0.11.0 — a `PackageProvider` abstract interface with Homebrew refactored into just one implementation, provider-resolution dispatch, provider-scoped manifest entries, uniform environment composition, and **a stub non-Homebrew provider proving the seam was real before any second concrete backend was written** — plus a built-in process supervisor replacing launchctl.

The v1 push followed in June: 🎯T73's release-candidate harness and publishing pipeline, then 🎯T74's five frontier checkpoints (multi-provider, SAT-solver dependency resolution, migration, deferred upgrades, host detection) and the v1 blockers cleared — trust model, source builds with taps, performance benchmarks — for +7,848 lines across 84 files. Framing resolution as a **SAT problem behind an explicit trust model** is what makes the RC defensible: "is this environment satisfiable?" becomes a decision procedure rather than a best-effort graph walk.

Since then the work has been operational hardening. A remote conviction-loop harness drives live `~/.den` scenarios over SSH against a physical `den-test-mac` (21 PASS/0 on the harness, 14/0/1 on the soak), Fable F1–F5 remediation closed archive-symlink escapes, env-slug `..` percent-encoding and fail-closed self-update checksums, and a Mach-O bottle-relocation fix stopped poured arm64 binaries being SIGKILLed for invalid codesign until `install_name_tool` rewrote their load commands. The most recent report fixes two silent-failure bugs in one daemon install — a macOS launchd path resolving its own binary through the Linux-only `/proc/self/exe` inside an `#ifdef __APPLE__` block, and `set_setting` inferring JSON type from the *existing* value so a first-time boolean was stored as the string `"true"` and skipped by the reader's `is_boolean()` check. The fix corrects the writer and teaches both readers to accept the legacy form so broken configs heal on next read; it landed without a regression test, which the report calls out as the week's one soft spot.
