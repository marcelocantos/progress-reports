# [marcelocantos/rustuml](https://github.com/marcelocantos/rustuml)

A pure Rust reimplementation of [PlantUML](https://plantuml.com) — a single statically-linked binary with no JVM, no Graphviz and no external fonts, pursuing byte-exact SVG parity with the Java original across an ~11,000-entry golden corpus.

## The journey

rustuml was created on a Saturday in late March and reached 18 diagram types before the weekend was out. The first week landed 43 commits carrying sequence, class, activity, state, component, deployment, use case, object, timing, ER, Gantt, mindmap, WBS, JSON, YAML, Salt, network and Ditaa diagrams, plus a TIM preprocessor (`!define`, `!include`, `!ifdef`, `!foreach`, `!function`, arithmetic, `while`), Creole markup, SVG/PNG/PDF/EPS output and a six-crate workspace. The decisive architectural choice was made in the same week: rather than read an enormous undocumented Java codebase, build a **golden test oracle** that renders a combinatorial matrix of inputs through both Java PlantUML and the Rust port and compares the results — 12,500+ golden pairs compressed from 25,000 files into a 4.3 MB zstd tarball read in memory. That turned an impossible specification problem into a measurable convergence problem.

The second phase chased the SVG output itself. Six renderers were rewritten for parity and v0.5.0 shipped as the "PlantUML parity" milestone, unlocked by the observation that **Java AWT font metrics are exact binary fractions** (character widths as n/16), so replacing truncated floats with exact values made coordinates match rather than merely approximate. The oracle framework was reworked to compare structural layout — element positions, text baselines, separator coordinates — sidestepping IEEE 754 divergence between the two runtimes. v0.6.0 added the slate default theme, a strict XML tree-equivalence comparator, and per-character width ratios reverse-engineered from 125,710 text elements across the golden SVGs, matching PlantUML's `textLength` with maximum error below 0.004 px.

Then came the long strict-XML push, most of it invisible on master for weeks. A segment-based Creole API (`parse_segments` → uniformly styled segments, `emit_text` as the single writer) produced PlantUML's no-`<tspan>` output shape, and JVM-extracted bold sans-serif metrics recovered a 172-pass regression. By late May the branch stack had grown to **203 unmerged commits** across `strict-xml-parity-renderers` and roughly eighteen `worktree-agent-*` branches with nothing on master. It merged on 2026-05-29 as **v0.7.0**, appearing as 269 landed commits — a shipping event rather than fresh authorship, with 30 mechanical [bullseye](bullseye.md) autosaves among them and roughly 35% of the +55k insertions being golden, `.puml`, test and SVG fixtures.

June was spent porting PlantUML's layout engines outright. A 377-commit week brought the `klimt/compress` whole-diagram compression pass, `FtileIfLongHorizontal`/`FtileWhile`/`FtileSwitch`/`FtileRepeat` tile geometry, fork-branch height models and swimlane `getMinMax` lane widths, alongside faithful Teoz sequence geometry — livebox constraints, group frames, note spans, participant-box alignment. The compression port is the sharp end: PlantUML slides tiles into row slack based on what counts as ON_X occupancy, so rustuml replicates `SlotFinder`'s accounting of connector polygons and paths rather than approximating it, which is what makes everything layered above it trustworthy.

That foundation carried the **second-generation swimlane engine**. swimlane-v2 tags every connector with its lane provenance first (a `LaneMark` node variant with `lane_spans` emit-tracking) and only then routes, so per-lane MinMax columns with ON_X occupancy and a cross-lane connector router compose without special cases — N-branch fork routing scales from simple through six-branch forks, lane-delimited combos and nested swimlane forks on the same machinery. Parity was then locked against **real-world diagrams** — restaurant, shopping-cart, onboarding, approval and expense workflows — on the principle that the golden which fails should be one a user would actually draw.

The most recent phase hardened the measurement itself. 🎯T14's `golden_no_oracle` tier renders every one of ~11,251 goldens through the real CLI with the oracle switched off and exact-matches a recorded baseline, so **a regression and an unrecorded improvement both fail the build**, while `harness_guards` freezes the anti-gaming constants (`GEOM_EPS`, the error-golden census) so the ratchet cannot be quietly loosened. rustuml develops on master with no PR ceremony when it lands at all; as of the latest report it carries **278 commits in-flight** (+64k/−10k), the largest unmerged tranche in the fleet.

## Standouts

- **A parity ratchet that refuses to round its own numbers** — `golden_no_oracle` renders all ~11,251 goldens through the real CLI with the oracle switched off and exact-matches a recorded baseline, so an unrecorded *improvement* fails the build exactly as a regression does; `harness_guards` freezes `GEOM_EPS` and the error-golden census so the ratchet itself cannot be loosened quietly. It is what turns "44.6% exact" into a number worth quoting. ([2026-07-05](../../reports/weekly-report-2026-07-05.md))
- **Java AWT font metrics are exact binary fractions** — PlantUML's coordinates land on values like 13.6875 because AWT character widths are n/16, not truncated floats. Substituting the exact fractions moved SVG output from "close" to "matching", and reframed golden comparison as structural equivalence rather than string equality, sidestepping IEEE 754 divergence between the two runtimes. ([2026-03-29](../../reports/weekly-report-2026-03-29.md))
- **Porting `klimt/compress` instead of approximating it** — PlantUML slides tiles into row slack according to what its `SlotFinder` counts as ON_X occupancy, down to connector polygons, paths and inter-diamond arrowheads. rustuml replicates that accounting exactly, which is the reason every layout layered above it can be trusted golden-by-golden. ([2026-06-14](../../reports/weekly-report-2026-06-14.md))
- **Lane provenance tagged before routing, not during** — swimlane-v2 marks each connector with its lane first, so per-lane MinMax columns and the cross-lane router compose without special cases and N-branch fork routing scales from simple forks through six-branch, lane-delimited and nested cases on one mechanism — all against an undocumented Java engine with no specification to consult. ([2026-06-21](../../reports/weekly-report-2026-06-21.md))
- **v0.7.0: 203 in-flight commits across ~18 branches landed at once** — weeks of strict-XML parity work sat on `strict-xml-parity-renderers` and a fan of `worktree-agent-*` branches with nothing on master, then merged as 269 landed commits. The report is explicit that this is a shipping event rather than a week of fresh authorship. ([2026-05-31](../../reports/weekly-report-2026-05-31.md))
