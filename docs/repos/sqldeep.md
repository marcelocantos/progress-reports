# [marcelocantos/sqldeep](https://github.com/marcelocantos/sqldeep)

sqldeep is a C++ SQL transpiler that adds deep expressions to SQLite and PostgreSQL — FROM-first syntax, FK-guided join path algebra, recursive tree construction, and XML/HTML literals — lowering all of it to standard JSON functions. It exposes a pure C public API with Go, Swift, and Kotlin bindings, and since v0.22.0 parses through a vendored Lemon LALR(1) grammar rather than a hand-written scanner.

## The journey

sqldeep began as a transpiler built from scratch in a single week: thirty-three commits, four releases, and 111 tests. The founding syntax is **FROM-first** — `FROM customers c SELECT { "name": c.name, "orders": ... }` — putting data flow top-down instead of SQL's inside-out nesting. On top of it sits a join path algebra where `c->orders` follows a conventional `<table>_id` foreign key, `<-` reverses it, chains compose (`c->orders o->items i`), and `c->custacct<-accounts` navigates a many-to-many bridge. A two-pass lexer pre-scans for alias resolution; explicit `ForeignKey` metadata handles non-conventional column names and multi-column composite keys. `SELECT/1` skips the `json_group_array()` wrapper and adds `LIMIT 1` for single-row projections. The effect is that verbose `json_group_array(json_object(...))` with manual JOINs becomes a declarative form that reads like its own output structure.

A PostgreSQL backend followed almost immediately, with backend-specific function mapping (`json_group_array` → `json_agg`, `json_object` → `json_build_object`) and shared YAML-driven test data covering both targets, alongside a consolidation onto C as the sole public API. The next release trio pushed into harder territory: `RECURSE ON` transpiles a recursive relationship into a **three-CTE bracket-injection template** — `_sdq_dfs` performs recursive DFS with cycle detection, `_sdq_ranked` numbers rows and generates JSON fragments, `_sdq_events` emits opening and closing bracket fragments positioned by DFS path — so a final `group_concat` over sorted events materialises a correctly nested JSON tree in one statement, no temporary tables, no cursors, no application code, on both backends. Dialect compatibility arrived in parallel (`--` comments, context-sensitive `->`/`->>`), as did aggregate fields, computed join keys, and a 744-line paper on the fixed-point comprehension semantics underlying the query model.

Then came a fifty-three-commit expansion into document output. XML and HTML literals became first-class SQL syntax — `SELECT <div class={category}>{name}</div>` transpiles to runtime function calls — with the fragile XML sentinel byte replaced by **SQLite's BLOB type as the transport protocol**, eventually going pure-BLOB in v0.18.0 by eliminating SQLite subtypes entirely. `jsx()` and `jsonml()` output modes layer over the same literal syntax, boolean attributes follow HTML conventions automatically, self-closing and non-void elements stay distinguished in output, and multi-line literals dedent to their common prefix. The XML SQLite functions were extracted into a shared `sqldeep_xml` module for reuse across bindings and an interactive CLI shell, and a `--help-agent` flag embedded a 306-line agents guide for AI coding agents. Ten releases, v0.9.0 through v0.18.0.

Multi-language bindings landed next: a Swift package with a `CSQLDeep` module and `SQLDeepRuntime`, a Kotlin/Android binding over a JNI bridge with Gradle instrumented tests, and a Go binding over CGo. The unifying move is a **single 918-line YAML test corpus of 79 cases** driving integration tests across C++, Go, Swift, and Kotlin — each runner is thin, parsing YAML, calling its binding's transpile function, executing the result, and comparing, so one new case runs on every platform at once. A `SQLDEEP_SQLITE_VANILLA` flag was added for environments without custom functions, generating pure SQLite that needs no XML runtime extension.

The last structural act was the parser rewrite. sqldeep had carried a hand-rolled partial-SQL scanner that silently mis-parsed anything it had not been taught. Vendoring **deepparser** — a Lemon LALR(1) grammar with a visitable AST, forked from `sqliteai/liteparser` — began with submodule plumbing and licensing correction, then three submodule bumps converged on full sqldeep grammar coverage: trailing commas, qualified bare fields, array-first JSON paths, FROM-first clause restructuring, bare-`SELECT` as a field value with FIELD_COMMA tokenisation, and backslash escapes in double-quoted identifiers, with 217 inputs parsing directly and 21 intentional error cases. `.gitmodules` gained `branch = sqldeep-grammar` so `git submodule update --remote` follows the long-running grammar branch rather than silently reverting to upstream `main`. v0.22.0 cut the whole pipeline over, deleting an entire class of "the scanner didn't understand this valid SQL" bugs at once.

Since then sqldeep has been in steady maintenance — a stale zlib linker dropped, `ar rcs` replacing macOS-only `libtool -static` for Linux CI portability, the `mk`→`cv` migration, a Node 24 CI bump — with one correctness release: v0.23.0 hardens positional-parameter handling so a reordering is detected and rejected rather than silently mis-bound. It remains a load-bearing dependency of [sqlpipe](sqlpipe.md), which bundles it behind the unified `Database` API, and of [mnemo](mnemo.md), which serves `mnemo_status` from a single nested sqldeep projection.

## Standouts

- **FK-guided join path algebra** — `c->orders o->items i` and `c->custacct<-accounts` resolve against foreign-key metadata, but composite multi-column keys need AND-joined conditions and multiple FK paths between the same pair of tables need disambiguation — a combinatorial problem that breaks naively recursive transpilation, solved with a two-pass lexer and explicit `ForeignKey` metadata. ([03-01](../../reports/weekly-report-2026-03-01.md))
- **A nested JSON tree built by injecting brackets** — `RECURSE ON` lowers to three CTEs: `_sdq_dfs` walks recursively with cycle detection, `_sdq_ranked` numbers rows and emits JSON fragments, `_sdq_events` emits opening and closing bracket fragments positioned by DFS path, so a final `group_concat` over sorted events materialises the tree in one statement — no temporary tables, no cursors, no application code, on both SQLite and PostgreSQL. ([03-15](../../reports/weekly-report-2026-03-15.md))
- **XML literals carried over SQLite's BLOB type** — `SELECT <div class={category}>{name}</div>` transpiles to runtime function calls, with the original fragile sentinel byte replaced by BLOB as the transport protocol and SQLite subtypes eliminated entirely by v0.18.0; getting an interactive shell into a single-file C++ transpiler meant vendoring 33K lines of `shell.c` and wiring it into the build. ([04-05](../../reports/weekly-report-2026-04-05.md))
- **Four languages, one test corpus** — a single 918-line YAML file of 79 cases drives integration tests across C++, Go, Swift, and Kotlin; each runner is thin enough to just parse, transpile, execute, and compare, so one new case runs on every platform at once rather than being ported four times. ([04-12](../../reports/weekly-report-2026-04-12.md))
- **Deleting a bug class instead of patching it** — the hand-rolled partial-SQL scanner silently mis-parsed anything it had not been taught; vendoring the `deepparser` Lemon LALR(1) grammar (tracked on a `sqldeep-grammar` branch so `--remote` cannot silently revert it) and cutting the whole pipeline over in v0.22.0 retired the entire category at once. ([05-24](../../reports/weekly-report-2026-05-24.md))
