# [marcelocantos/sqlpipe](https://github.com/marcelocantos/sqlpipe)

sqlpipe is a streaming bidirectional replication protocol for SQLite, built on the session extension and shipped as a C++ core with Go, Swift, WebAssembly, and TypeScript bindings. It carries changesets between peers, drives live query subscriptions through a relational-algebra predicate engine, and bundles [sqldeep](sqldeep.md) transpilation and [sqlift](sqlift.md) migration behind a unified `Database` API.

## The journey

sqlpipe opens the series as a greenfield library. The founding insight is that SQLite's session extension captures row-level changesets as they happen, and that changesets are self-describing, composable, and idempotently applicable — so replication reduces to serialising them over any byte stream. The first week landed a master/replica architecture with a state-request handshake, changeset framing, and resync, then immediately evolved it into a symmetric `Peer` that returns change events from `handle_message` instead of invoking callbacks, making conflict resolution deterministic. Query subscriptions, a hash-exchange diff-sync protocol, 60+ test cases, and a vendored SQLite compiled with session and preupdate hooks came in the same window.

The next fortnight thickened the protocol and widened the surface. LZ4 changeset compression with per-message marking and uncompressed fallback, `on_schema_mismatch` migration hooks, batched `handle_messages()` deferring subscription re-evaluation, message size limits, and a `reset()` that returns to Init while preserving subscriptions or table ownership took it through v0.6.0. Query subscriptions gained automatic dependency discovery by driving SQLite's authoriser API over the registered SQL, so subscribers are notified only when results actually change. Then came portability: a Go wrapper via CGo, spdlog swapped for user-provided callback logging to drop a compiled dependency, sqlift v0.12.0 wired in for schema fingerprinting, an Emscripten **WebAssembly build** with a TypeScript wrapper and a live browser demo running bidirectional SQLite sync entirely client-side, and a self-contained Go wrapper that dropped `mattn/go-sqlite3` and owns the raw `sqlite3*` handle through a CGo trampoline.

Topologies and optimistic UI arrived next. A `Relay` class enabled source → relay → sink chain replication and fan-out from one master to N replicas, with sequence-gap rejection preserving consistency; the relay is a thin passthrough applying the same changeset logic as any peer, so it inherits the base protocol's guarantees. The prediction API took a deliberately simple route to optimistic updates — wrap the local mutation in a SQLite savepoint so rollback is one `ROLLBACK TO` regardless of mutation complexity, eliminating per-mutation undo logic. Protocol v6 added fast reconnect that skips full diff sync when sequence numbers match, an explicit `PeerRole::Server`/`PeerRole::Client` designation replaced implicit server detection (fixing a stress-test SIGSEGV), and Swift Package Manager and standalone `go get` consumption both landed by bundling the C/C++ sources.

The intelligence layer is the project's high-water mark. Subscription queries are analysed into a relational algebra representation with predicate pushdown through joins, predicate splitting across multi-table subscriptions, join normalisation, and transitive propagation through equijoins — from `a.x = b.x` and `a.x > 5`, infer `b.x > 5`. Predicates compile to a **stack-based bytecode VM** with `LoadCol`, comparison, logical, and `InList` operators that evaluates changesets without runtime SQL parsing, backed by OR-to-InList optimisation, `NOT IN`, and three-valued NULL semantics. Column relevance tracking skips `UPDATE` changesets touching only irrelevant columns, turning O(subscriptions × changes) invalidation into O(relevant changes). Beside it came a **stateless convergence loop** — peers exchange content-addressed bucket hashes, identify divergent buckets, and reconcile with no handshake, no session state, and no exactly-once requirement, proven convergent by a TLA+ model and tested end-to-end through a [pigeon](pigeon.md) relay (then still named tern).

Consolidation followed. A unified `sqlpipe::Database` wrapped SQLite with bundled sqldeep transpilation and sqlift middleware so applications write enhanced SQL — deep expressions, XML literals — and sqlpipe transpiles transparently; glob patterns landed for table ownership; `Delivery`, `OutMessage`, and `PeerOutMessage` were deleted on the grounds that messages are just messages. sqlpipe then went quiet for two months of maintenance: diff-sync benchmarks, ccache wiring shared across the C/C++ fleet, the `targets.yaml` → `bullseye.yaml` rename, bundled sqlift bumps carrying the strict-by-default apply policy through sqlpipe's C surface, the `mk`→`cv` migration, and a re-vendored amalgamation in v0.24.0 whose +15,397/−16,031 is almost entirely vendor churn.

The Fable-5 audit reopened it. Two critical, six high, and one medium finding came with compiled live reproductions: diff sync keyed rows by `rowid` rather than PRIMARY KEY, wiping content-identical TEXT and composite-PK tables, and a `flush_pending` that was never reset streamed a phantom row from a committed-then-rolled-back transaction into permanent replica divergence. All nine were fixed in v0.25.0 across `dist/sqlpipe.cpp` and mirrored into the Go and Swift copies, with roughly eight C++ doctest cases mapping 1:1 onto the targets — +1,535/−120, largely triplicated across mirrors. v0.26→v0.28 replaced a lossy 32-bit schema fold with the **full structural fingerprint** across the C++ core and all three binding mirrors, cutting false schema-equality collisions, and vendored the `deepparser` Lemon parser into `CSqlpipe` so the Swift package builds standalone — the +19,289/−867 headline is ≈16.8k vendored parser against ≈1.2–1.6k authored, triplicated. v0.29→v0.30 closed with `_sqlpipe_meta` preserved across `Database` reopen and richer migration diagnostics.

([03-01](../../reports/weekly-report-2026-03-01.md))
- **Go wrapper and schema fingerprinting** — CGo bindings for the C API, spdlog replaced by user-provided callback logging, and sqlift v0.12.0 integrated for cross-replica drift detection. ([03-08](../../reports/weekly-report-2026-03-08.md))
- **WebAssembly build** — compiled through Emscripten with a TypeScript wrapper class and a live browser demo running bidirectional SQLite sync entirely client-side; the Go wrapper simultaneously dropped `mattn/go-sqlite3` for a zero-dependency raw-handle design. ([03-15](../../reports/weekly-report-2026-03-15.md))
- **Chain replication** — a `Relay` class for source → relay → sink topologies plus one-master-to-N-replicas fan-out, with sequence-gap rejection, inheriting the base protocol's consistency guarantees. ([03-22](../../reports/weekly-report-2026-03-22.md))
- **Savepoint-based prediction API** — optimistic local mutations wrapped in a SQLite savepoint, so rollback is a single `ROLLBACK TO` regardless of mutation complexity and no per-mutation undo logic is needed. ([03-22](../../reports/weekly-report-2026-03-22.md))
- **Relational algebra engine with a bytecode VM** — predicate pushdown, splitting, and transitive propagation through equijoins, compiled to a stack-based VM, with column-relevance tracking that skips irrelevant-column updates entirely. ([03-29](../../reports/weekly-report-2026-03-29.md))
- **Stateless convergence loop** — bucket-hash exchange with no handshake, no session state, and no sequence numbers, TLA+-verified to converge in bounded rounds under loss, reordering, and restart. ([03-29](../../reports/weekly-report-2026-03-29.md))
- **Unified `Database` API** — SQLite wrapped with bundled sqldeep transpilation and sqlift middleware, so applications write enhanced SQL (deep expressions, XML literals) and sqlpipe handles the rewrite transparently. ([04-05](../../reports/weekly-report-2026-04-05.md))
- **Audit and full remediation (v0.25.0)** — nine findings fixed, including a diff sync keyed by `rowid` instead of PRIMARY KEY that wiped content-identical tables, and a never-reset `flush_pending` that streamed a phantom row into permanent divergence. ([07-05](../../reports/weekly-report-2026-07-05.md))
- **Full structural schema fingerprint** — a lossy 32-bit fold replaced by the complete structural hash across the C++ core and all three binding mirrors, cutting false schema-equality collisions; `deepparser` vendored into `CSqlpipe` for a standalone Swift build. ([07-12](../../reports/weekly-report-2026-07-12.md))
- **Reopen-safe metadata and migration diagnostics** — v0.29→v0.30 preserved `_sqlpipe_meta` across `Database` reopen and enriched migration diagnostics, with dual-channel transport tests. ([07-19](../../reports/weekly-report-2026-07-19.md))
- **Replica prediction across three languages** — `begin`/`commit`/`end`/`rollback_prediction` and `queue_while_predicting` exposed through CGo with a Swift `TruthReplica`, shipped in the same week as its first consumer (v0.31.0). ([2026-08-09](../../reports/weekly-report-2026-08-09.md))

## Standouts

- **A predicate bytecode VM over relational algebra** — subscription queries are analysed into relational algebra with predicate pushdown, splitting across multi-table subscriptions, and transitive propagation through equijoins (from `a.x = b.x` and `a.x > 5`, infer `b.x > 5`), then compiled to a stack-based VM with three-valued NULL semantics that evaluates changesets without ever parsing SQL at runtime. ([03-29](../../reports/weekly-report-2026-03-29.md))
- **A convergence loop with no handshake and no session state** — peers exchange content-addressed bucket hashes, identify divergent buckets, and reconcile with no exactly-once requirement, proven convergent under loss, reordering, and restart by a TLA+ model and tested end-to-end through a real relay. ([03-29](../../reports/weekly-report-2026-03-29.md))
- **Diff sync keyed by `rowid` instead of PRIMARY KEY** — the Fable-5 audit's live reproduction showed content-identical TEXT and composite-PK tables being wiped, and a `flush_pending` flag that was never reset streaming a phantom row from a committed-then-rolled-back transaction into permanent replica divergence; both were silent, both were fixed in v0.25.0. ([07-05](../../reports/weekly-report-2026-07-05.md))
- **Deterministic conflict resolution by deleting the callbacks** — simultaneous writes on both peers can deliver changesets out of causal order; rather than add ordering machinery, `Peer` serialises application through a single event loop and *returns* change events from `handle_message` instead of invoking callbacks, which makes the resolution order an observable property of the API. ([02-22](../../reports/weekly-report-2026-02-22.md))
- **Bidirectional SQLite sync running entirely in a browser** — an Emscripten WebAssembly build with a TypeScript wrapper and a live client-side demo, landing the same week the Go wrapper dropped `mattn/go-sqlite3` for a zero-dependency raw-handle design. ([03-15](../../reports/weekly-report-2026-03-15.md))
