# [squz/ge](https://github.com/squz/ge)

ge is the shared C++ mobile game engine behind [multimaze2](multimaze2.md), [esfera2](esfera2.md) and [yourworld2](yourworld2.md): a sokol_gfx renderer, a canonical 2D/UI surface, cross-platform in-app purchasing, and a location-transparent command stream that runs the same game on iOS, Android, desktop and the browser.

## The journey

ge was not founded; it was carved out. Through late January and early February the rendering, resource and build machinery inside [yourworld2](yourworld2.md) was moved into an `sq/` directory and then **fully separated into a standalone submodule**, with `Module.mk` namespacing every target, source list and flag under an `sq/` prefix, the host linking a single `libsq.a`, and includes switched to angle-bracket `<sq/...>` so the boundary was visible in source. That structure is what let [esfera2](esfera2.md) adopt the engine within weeks. The submodule was **renamed `sq` → `ge`** across `.gitmodules`, Makefiles, includes and namespaces in late February, and later repointed to the `squz/ge` organisation.

The next phase was renderer churn driven by an ambition to render remotely. Dawn/WebGPU was deleted and bgfx became the sole renderer; a `RenderBackend` abstraction split real rendering from a `SceneWriterBackend` that records commands to a scene display-list protocol, and a `NetworkBackend` went further by **implementing bgfx's internal `RendererContextI`** to intercept and serialise texture creation, uniform updates and draw calls for replay against a real Metal backend on a remote player — 1,418 resources flowing server to player. It hit a wall: bgfx's internal state is not designed for multiple instances. The work pivoted to H.264 streaming with a zero-copy Metal `IOSurface` path into VideoToolbox, and the pivot week also collapsed 140 lines of per-game boilerplate into a single `ge::run()` entry point with the engine owning the SQLite handle and signal handlers.

By April ge became a product rather than a directory. The engine/render/bridge split behind a `RenderHost` interface shipped as **v0.1.0**, together with an in-tree `tiltbuggy` sample consumed exactly the way a downstream game consumes it — `add_subdirectory(ge)` plus the APP_NAME convention — so the canonical integration pattern is a working, device-tested app rather than prose. `ge_wire.yaml` then made the player-to-session-host wire protocol a single declarative source feeding protogen bindings in Go, Swift, Kotlin, C and TypeScript, turning schema drift into compile errors. May brought **eighteen minor releases in five days** (v0.5.0 → v0.22.0) that grew the public API from rectangles and safe areas into a complete canonical 2D/UI surface: `pixelsPerPt()`/`deviceUiScale()` for physical-size sizing, device-tilt parallax via `CMMotionManager` and `GAME_ROTATION_VECTOR`, the engine-owned `ge.GeActivity` ending per-app Activity drift, lunasvg as the canonical SVG rasteriser with lazily bootstrapped system fonts, the `loadTexture2D`/`rasterizeText`/`SpriteBatch` asset pipeline, a one-source-SVG app-icon generator, and a constexpr audit pinned by a compile-time regression TU. A cross-platform IAP module followed — `<ge/iap.h>` over StoreKit (later a StoreKit 2 Swift bridge) and Play Billing 7+ through a JNI `ge.IapBridge`.

Then the renderer was replaced again, for keeps. **bgfx gave way to sokol_gfx** in v0.36.0, alongside prebuilt vendor static libraries for iOS and Android arm64 with a staleness verifier, a single source-of-truth manifest, and the iOS build's cutover from CMake to a Ruby `xcodeproj` builder. Diagnostics and portability grew around it: a backend-agnostic `ge::debug` overlay that is a cheap no-op while disabled so call sites stay unconditional; the `ge::appchannel` MessagePack-RPC counterpart to [spyder](spyder.md); Android Vulkan with a GLES3 fallback chosen by a runtime capability probe *before* any backend code executes; a SpriteBatch overflow buffer-pool that bounds transient Metal driver pressure; headless render-to-PNG turning GPU output into a comparable pure function; and a camera-basis `GlobeController` that resolves drags in the viewer's frame rather than world axes. In early July the **bgfx eradication** completed — vendored submodules deleted, a −42,729-line purge — with a render-on-demand tier that idles a static scene and a TiltBuggy differential-physics oracle that runs the revived 2013 original on real Chipmunk headless as executable ground truth for the box2d reimplementation.

Consolidation followed. "Plateau P" retired the entire `ged` Go daemon and its React tweak console outright (−12,630 lines) once every capability had been re-proven on spyder's app-channel, leaving spyder the sole control plane. In the same window [esfera2](esfera2.md) and [yourworld2](yourworld2.md) both landed on the sokol_gfx backend, which is what turned "the yourworld engine" into a genuine multi-title substrate. A week later ge gained a **fourth direct-mode platform**: an [Emscripten](https://emscripten.org/)/WebGL2 target where an unmodified consumer `main.cpp` builds to `.html/.js/.wasm`, keeping the native blocking run loop and suspending via RAF-aligned Asyncify under a documented contract — `ge::run` is `noexcept`, SessionHost compiles without exceptions, sqlite fsync is compiled out — because Asyncify cannot suspend beneath a JS frame. Alongside it the location-transparent command stream (`CmdStream`, `StreamHostPolicy`, `SeatPolicy`, `ViewerMetrics`) established sensor authority and per-session game instances, making a browser tab and a phone interchangeable seats.

The most recent window is about cooking and measuring. A **compressed-texture pipeline** puts the encoder choice in the output extension of a new `bin/ge-texenc` CLI backed by statically built astc-encoder and etcpak (cook path only — neither is linked into `libge.a`), with Make pattern rules so consumers just declare the cooked artefact; at runtime `ge::loadTexture` queries `sg_query_pixelformat` and walks an ordered ASTC → ETC2 → PNG candidate list, so games never branch on encoding. A **zero-I/O per-instance frame-metrics ring** exists because diagnosing a carousel hitch by logging per frame perturbed the timing under investigation: capture is a single guarded assignment, rings bind to a game instance rather than a global, and the surface compiles out under `NDEBUG`. Rounding the window out: an automated 287-line SDL3 3.4.12 prebuilt recook producing seven xcframeworks, sensor authority added without breaking the constructional invariant that had made arbitration unnecessary, and `hit_targets` exporting button identity so spyder can address UI by id and role and never by display label.

## Standouts

- **A remote renderer that hit the renderer's own limits** — implementing bgfx's internal `RendererContextI` to intercept and serialise texture creation, uniform updates and draw calls got 1,418 resources replaying against a real Metal backend on a remote player, then stopped dead because bgfx's internal state is not designed for multiple instances; the work pivoted to H.264 over a zero-copy Metal `IOSurface` path into VideoToolbox. ([2026-04-05](../../reports/weekly-report-2026-04-05.md))
- **Eighteen releases in five days** — v0.5.0 → v0.22.0 grew the public API from rectangles and safe areas into a complete canonical 2D/UI surface: physical-size sizing, device-tilt parallax, the engine-owned `ge.GeActivity`, lunasvg with lazily bootstrapped system fonts, the `loadTexture2D`/`rasterizeText`/`SpriteBatch` pipeline and a constexpr audit pinned by a compile-time regression TU. ([2026-05-10](../../reports/weekly-report-2026-05-10.md))
- **A capability probe before any backend code runs** — sokol's Vulkan backend is no one-flag swap: ge owns the instance, device, queue and swapchain, so a runtime Vulkan loader and generated dispatch table decide Vulkan-vs-GLES3 *before* a single Vulkan entry point is touched, routing unsupported devices to the guaranteed fallback instead of crashing on them. ([2026-06-07](../../reports/weekly-report-2026-06-07.md))
- **An executable 2013 game as the parity oracle** — the revived original TiltBuggy runs headless on real Chipmunk and serves as differential ground truth for the box2d reimplementation, landing in the same window as the bgfx eradication (−42,729 lines). ([2026-07-05](../../reports/weekly-report-2026-07-05.md))
- **Asyncify as a contract, not a flag** — the Emscripten/WebGL2 target keeps the native blocking run loop and suspends via RAF-aligned Asyncify, which is only sound under stated obligations — `ge::run` is `noexcept`, SessionHost compiles without exceptions, sqlite fsync is compiled out — because Asyncify cannot suspend beneath a JS frame. ([2026-07-19](../../reports/weekly-report-2026-07-19.md))
- **A metrics ring because logging changed the answer** — diagnosing a carousel hitch by logging per frame perturbed the very timing under investigation, so capture became a single guarded assignment into a ring bound to a game instance rather than a global, compiled out entirely under `NDEBUG`. ([2026-07-26](../../reports/weekly-report-2026-07-26.md))
